01

RELIABLE WORKFLOW

设备缺陷如何可靠流转到安全隐患？

设备 → 安全
对应 GitHub 仓库设备点检仓库 ↗安全管理仓库 ↗Outbox 源码 ↗接收接口源码 ↗

问题

设备端发送缺陷后，如果安全端已保存、但回执丢失，简单重试可能重复创建隐患；直接依赖一次网络请求也可能造成漏传。

实现

设备端采用事务性 Outbox（待发消息表）：将业务变更与待发送消息放在同一事务，保存不可变消息快照；安全端将接收收据与隐患记录原子保存。接收端以身份键防重；相同内容重试返回已有结果，不同内容返回 HTTP 409 冲突。发送端校验回执身份后再标记成功。

验证

使用两个独立应用和数据库，通过 HTTP 代理故意丢弃首次回执；重启发送进程并改变源数据后，重试仍使用原消息，结果只有一条隐患和收据。

边界：传输允许重复；不声称跨数据库“恰好一次”，也不代表现场部署验证。
设备端 PR ↗安全端 PR ↗验证证据 ↗

02

DATA LINEAGE

煤质数据如何进入能效分析？

煤质 → 能效
对应 GitHub 仓库煤质检验仓库 ↗燃煤能效仓库 ↗煤质适配源码 ↗时间依据源码 ↗

问题

热值数字必须同时说明单位、基准、来源和时间。煤批显示名称相同，也不能直接认定为同一实体。

实现

煤质端导出来源实例、批次、化验和带时区的测量数据；能效端保存测量与操作者提交的时间依据，通过明确选择的情景关联 ID 预览。校验来源、时间和基准，使用 UUID 请求标识实现幂等与冲突保护，并以 SHA-256 标识接收内容版本。

验证

双应用契约使用合成化验记录，验证 4000 kcal/kg 按 4.1868 换算得到 16747.2 kJ/kg，同时检查错误来源与时间声明被拒绝，预览不写入运行快照。

边界：时间依据是操作者声明；情景关联和煤场账面出场均不证明真实入炉。
煤质契约 PR ↗能效端 PR ↗验证记录 ↗

03

INVENTORY & QUALITY

库存和数字输入如何避免明显错误？

数量与一致性
对应 GitHub 仓库煤场管理仓库 ↗设备采购仓库 ↗FIFO 出场源码 ↗数量校验源码 ↗

设备采购侧使用 Decimal 管理数量与金额，校验容量和超量收货；煤场出入场统一限制有限数量与千分吨精度，FIFO 扣减使用十进制计算。煤场已可导出经校验的账面出场依据，并显式说明其只能反映当前数据库状态。

验证：煤场数量改动在 SQLite 完整回归 53 项通过，隔离 PostgreSQL 相关回归 51 项通过。设备采购及联动批次的完整设备后端回归 608 项通过；这些数字来自各自固定版本与不同测试范围，不能直接相加。

边界：煤场盘点调差和跨入口并发保护仍待完善；账面扣减不等于物理煤流。
煤场数量 PR ↗账面依据 PR ↗煤场验证记录 ↗
04

MODEL EVALUATION

模型结果如何避免被误读？

能效分析
对应 GitHub 仓库燃煤能效仓库 ↗模型评估源码 ↗后端测试代码 ↗

能效原型按时间顺序以前 80% 数据训练、后 20% 验证，比较训练集均值基线。原型策略要求至少 24 个有效样本、验证集平均绝对误差 MAE 不超过 5 g/kWh，且相对基线改善超过 10%；未满足条件或输入超出支持范围时采用规则降级。保留输入和评估依据，便于回看结果。

这些阈值是项目原型策略，并非行业验收标准。当前推荐氧量使用负荷经验公式，回归主要用于收益估算；预测评分不等于经过校准的故障概率，也不能证明实际节煤收益。
